# 热点话题抓取标准

## 选题池策略

热点抓取不再只按固定领域做窄筛选。默认采用双轨制：

1. `主线题`：稳定服务账号人设的日常选题池。
2. `流量实验题`：用于测试更大微信推荐流潜力的发散选题池。

两条轨道都必须有真实来源、可解释的讨论信号或权威信号，并且能进入作者的表达方式。区别在于范围边界和风险标记。

## AI 快速信号入口

AI 话题默认先使用 `skills/aihot-signal/SKILL.md` 扫描 AI HOT，再进入社交平台验证。

- AI HOT 用于快速发现近期新闻、产品、模型、论文和实践线索。
- 聚合摘要、selected 状态和站内 score 只代表入口信号，不代表事实已经核验，也不代表微信流量潜力。
- 候选必须保留原文 URL；进入研究前回到原文或官方来源核验关键事实。
- 完整热点收集仍必须覆盖默认社交信源，用真实讨论判断情绪、饱和度和剩余时间窗口。

### 主线题范围

主线题仍围绕账号的核心方向，但允许从窄 AI 工具话题扩展到邻近领域：

- AI 与科技
- 职场与职业变化
- 学习、技能形成与普通人适应新工具
- 组织管理、团队协作与岗位重排
- 创作者经济、个人生产系统与内容分发
- 平台规则、推荐机制与表达方式变化
- 判断力、注意力与 AI 时代的决策方式

### 流量实验题范围

流量实验题可以更宽，但不能变成泛热点追逐。可进入候选池的宽领域包括：

- 教育与学习焦虑
- 消费和效率幻觉
- 情绪、关系与现代生活压力
- 社会变化下的普通人处境
- 媒介习惯、平台机制和公共讨论方式

保留条件：

- 能被拉回“普通人在技术、工作、平台、学习或时代变化中的处境”
- 能从具体场景长出判断，而不是只复述热点
- 有长尾阅读价值，不只是一天内的热闹
- 输出时必须标记为 `流量实验题`，不得静默替代主线题

### 专家信源候选

国外专家文章、论文、演讲、newsletter、机构报告等单独作为 `专家信源候选`。它可以支撑主线题，也可以支撑流量实验题。

处理方式：

- 不默认全文翻译
- 优先做观点提炼、转述、评论和中文语境化
- 必须说明“这对中文读者/普通上班族/创作者有什么用”
- 必须保留原始来源指针
- 涉及版权内容时只做短引用和摘要，不做长篇搬运

## 两条核心标准（必须同时满足）

### 1. 不过于老旧

| 类型 | 可接受范围 | 说明 |
|------|-----------|------|
| 突发新闻 / 地缘政治 | **24小时内** | 这类话题爆发快、消退也快 |
| 产品发布 / 融资消息 | **7天内** | 话题有长尾，会持续发酵 |
| 深度分析 / 职场叙事 | **30天内** | 这类内容本身就有延迟，不追求"最新" |

**判定方法**：找到帖子的 `datetime` 属性（Twitter），或帖子时间戳（Reddit/V2EX）。

### 2. 有形成一定讨论度

时间新不等于值得写。**必须有活跃的讨论信号**：

- **Twitter/X**：`f=live` 模式下，搜索结果本身就是讨论信号。再看：转发数、回复数、同一话题多账号同时发帖
- **Reddit**：点赞数、评论数、是否出现在多个子版块
- **V2EX**：回复数、节点热度
- **知乎**：关注数、回答数

**判定方法**：扫描抓取结果时，同时提取时间和热度数字。有时间戳但零互动 → 可疑，需要跳过或降低优先级。

### 平衡长尾

真正热的话题会持续发酵，不需要盲目追"刚刚发布"。判断标准始终是：
> **最近有没有人在讨论**（转发/回复/点赞），而不是纯粹看发布时间。

对 `流量实验题` 和 `专家信源候选`，允许“不是最新，但最近被重新讨论”的候选进入初筛。此类候选必须写明长尾信号，例如：

- 旧文章或论文被多位近期创作者重新引用
- 社交平台出现新的争论、误读或实践案例
- 中文读者最近出现对应痛点
- 平台推荐或搜索中仍持续出现相关问题

## 平台健康状态

平台可用性是每次运行时事实，不在长期文档中写死“已验证”。正式采集前按 `docs/operations/web-access-setup.md` 记录本轮状态：

- `可用`：真实内容列表可见，能提取来源链接、发布时间/新鲜度信号和互动指标。
- `受限`：页面可达，但登录、验证码、地区限制、加载不完整或字段缺失导致证据不足。
- `不可用`：无法访问目标内容，只有登录页、错误页或页面壳，或没有可提取内容。

HTTP 200、页面标题存在、首页可打开或客户端脚本已加载，都不能单独证明数据可用。

## 仓库默认信源覆盖规则

### 主信源（默认必须先扫）

- `Twitter/X`
- `知乎`
- `小红书`
- `即刻`
- `微博`

这些平台必须通过当前运行环境提供的浏览器逐一尝试并记录健康状态，再决定候选池。完整社交讨论验证必须满足：`X` 可用、至少两个中文主社交平台可用、主信源合计至少三个平台可用。

### 定向账号搜索（可选增强）

如果本地存在 `docs/references/source-watchlist.md`，可以在主信源社交扫之后增加一轮定向账号搜索，用于补充来自机构、研究者、产品负责人和实践型创作者的一手信号。没有本地观察列表时跳过本轮，不使用仓库维护者的个人关注列表作为默认值。

定向账号搜索不是替代平台关键词扫，而是补充以下信息：

- 一线机构和关键人物的最新发布
- 实战派账号分享的工具、工作流、prompt、教程和方法论
- 平台关键词扫不容易发现的早期讨论线索

默认时间窗：

- 扫描最近 7 天内容
- 对突发事件仍按 24 小时规则提高优先级
- 超过 7 天的账号内容只能作为背景，不进入热点候选池

观察列表模板见 `docs/references/source-watchlist.example.md`。真实列表保存在被 Git 忽略的 `source-watchlist.md`，只允许包含公开账号和公开内容入口。

推荐搜索词：

- `tool`
- `workflow`
- `method`
- `tutorial`
- `prompt`
- `tip`
- `guide`
- `framework`

筛选优先级：

1. 立刻能用：工具、插件、应用、分步教程、prompt 模板、工作流技巧
2. 可复用方法论：内容创作流程、AI 使用最佳实践、生产力技巧、skill 构建框架
3. 思维转变：专家对 AI 使用方式、常见误区和使用模式的洞察

排除项：

- 纯技术基础设施、GPU/TPU/算力内容
- 网络安全专业内容
- 完全没有应用路径、中文语境化空间或现实痛点映射的学术论文
- 对个人或内容生产没有直接帮助的企业/B2B 公告
- 融资、营收新闻
- 单纯模型基准测试和技术对比

质量测试：

> 内容创作者读完后，能否立刻应用到工作中改进效果？

如果答案是“否”，降低优先级或排除。

对 `专家信源候选`，额外执行一个问题：

> 这篇专家材料能不能被改写成“普通人现在为什么要关心”的中文文章？

如果答案是“否”，只作为背景材料，不进入候选题列表。

## 推荐流潜力评分

每个候选题除了 freshness、discussion、relevance，还要评估推荐流潜力。可用 `高 / 中 / 低` 标记，也可以用 1-5 分。

| 维度 | 判断问题 |
|------|----------|
| 推荐流潜力 | 非粉丝能否在标题和前两段迅速理解并关心？ |
| 人群痛点 | 是否触及普通人、上班族或管理者真实会卡住的问题？ |
| 长尾价值 | 过几天或几周后是否仍值得读？ |
| 作者适配度 | 是否能从具体场景进入，再长出判断？ |
| 资料可靠性 | 是否有真实讨论、权威来源、专家文章或论文支撑？ |
| 收藏/转发理由 | 读者是否有保存、转发给同事朋友或二次讨论的理由？ |
| 账号风险 | 是否会稀释账号身份，变成泛热点？ |
| 话题饱和度 | 微信和社交平台是否已经出现大量同质表达，还有没有新角度？ |
| 时间窗口 | 话题处于打开、上升、峰值还是关闭阶段？ |

排序时不要只看热度。优先选择：

1. 推荐流潜力高
2. 账号风险可控
3. 能写出个人化的真实处境和判断
4. 有可靠来源支撑

### 流量下注分组

- `重仓`：读者钩子清楚、时间窗口仍开、资料足够且存在可辨识的新角度，可以优先进入研究。
- `轻仓`：有潜力但仍缺一个关键验证，或受众较窄、窗口稍弱，适合候补或快速补证。
- `观察`：信号真实但讨论尚未形成、事实仍不稳定或切入点不成熟，暂不消耗完整研究成本。
- `放弃`：情绪冷、过度饱和、无法拉回账号视角、需要夸大才成立，或事实风险不可接受。

每个 `重仓` / `轻仓` 候选都要说明读者钩子、时间窗口、饱和度和反向风险。分组是本项目判断，不沿用聚合站 score。

### 补充信源（主信源之后）

- `Reddit`
- `V2EX`

这两类平台用于交叉验证、补充中文/英文讨论面，不替代主信源社媒扫描。

### 禁止的降级方式

- 不得一开始就只做公开网页检索来替代登录态社媒抓取
- 不得因为某个平台抓取麻烦，就单方面略过主信源
- 页面返回 HTTP 200、标题或页面壳时，不得在没有内容列表、发布时间/新鲜度字段和互动指标的情况下标记为 `可用`
- 如果浏览器登录态或主信源平台访问异常，必须停止并告知用户，再决定是否继续缩减来源

## 浏览器抓取稳定性规则

### 基本原则
- 社交讨论验证使用用户明确指定、且具备本轮登录态的浏览器表面；项目不绑定浏览器品牌、扩展或本机 profile。
- 单个临时工作标签页顺序抓取优先，避免多标签并行导航造成内容串扰。
- 只关闭或释放本次任务创建的标签页，不操作用户原有标签页。
- 若目标页面要求登录，在当前浏览器中请用户登录；不要切换浏览器或公开搜索来绕过登录。

### 推荐流程
1. 选择用户明确指定、且具备所需登录态的浏览器表面。
2. 用运行环境支持的只读轻量操作探测连接。
3. 不得用一次空列表、超时或通信失败推断浏览器或连接器未安装。
4. 新建一个临时工作标签页，顺序导航五个主信源并执行内容级健康检查。
5. 达到覆盖门槛后采集候选；未达到时停止并披露缺口。
6. 完成后释放本次创建的临时标签页。

## 各平台操作规范

### Twitter/X
- 优先使用 `f=live`（实时讨论流），而非 `f=top`（热门但含历史帖）
- 抓取后必须提取每条的 `datetime` 属性，过滤掉超过7天无新讨论的
- 关注同一话题是否有多个账号同时在讨论（爆发信号）
- 中文搜索时注意 URL 编码问题
- 如果只加载出客户端页面壳、登录页或没有 `time`/互动字段，标记为 `受限` 或 `不可用`

### Reddit
- 优先尝试能稳定显示帖子列表的 Reddit 页面；具体入口以本轮健康检查为准
- 关注每个帖子的 `time-ago` 或 Unix 时间戳
- 优先选择： upvotes > 100 OR comments > 20 的帖子

### V2EX
- 节点 + 回复数双重过滤
- 优先 tech、程序员、iOS、Android 等相关节点

### 知乎
- 优先检查热榜 `zhihu.com/hot`；若要求登录，在当前浏览器中请用户登录
- 关注热度数字（万热度）和排序位置
- AI 相关话题常有高质量深度回答

### 小红书
- 优先检查搜索结果或 `xiaohongshu.com/explore`；是否需要登录以本轮页面状态为准
- 列表页没有发布时间时，打开少量候选详情核对，不用无时间信息的卡片证明新鲜度
- 关注点赞数和评论数

### 即刻
- 优先检查 `web.okjike.com` 的动态或话题页；若要求登录，在当前浏览器中请用户登录
- 关注 AI、产品经理、科技相关话题

### 微博
- 优先检查 `s.weibo.com/hot` 和站内搜索；登录需求以本轮页面状态为准
- 关注转发数和评论数

### 其他渠道（知乎热榜、微博、即刻）
- 同上：时间戳 + 互动数双重校验
- 知乎热榜本身已排序，但需验证内容与写作方向的契合度

## 执行流程

1. **搜索/抓取** → 获取原始结果
2. **AI 快速信号** → AI 话题先用 AI HOT 建立候选，不在此时采信聚合摘要
3. **来源健康检查** → 用浏览器逐一检查 `X / 知乎 / 小红书 / 即刻 / 微博`，记录登录态、内容列表、可提取条目数、发布时间/新鲜度字段、互动指标和健康状态
4. **覆盖门槛** → `X`、至少两个中文平台、主信源合计至少三个平台可用；否则停止并告知用户
5. **主信源社交扫** → 对通过健康检查的平台采集讨论信号
6. **定向账号搜索（可选）** → 如果存在本地观察列表，补充其中公开信源最近 7 天内容
7. **补充验证** → 用 `Reddit / V2EX` 和公开搜索做交叉验证或背景补充
8. **轨道标记** → 标记为 `主线题` / `流量实验题` / `专家信源候选`
9. **时效、长尾与饱和度过滤** → 删除明显超窗、缺乏再讨论价值或高度同质化的条目
10. **热度校验** → 删除零互动且无权威来源支撑的条目
11. **推荐流潜力评分** → 评估推荐流潜力、人群痛点、长尾价值、作者适配度、资料可靠性、收藏/转发理由、账号风险、饱和度和时间窗口
12. **实用价值过滤** → 对定向账号结果执行“立刻能用”测试；对专家信源执行“中文读者为什么要关心”测试
13. **人工复核** → 快速扫一眼，删除明显陈旧、圈层过小、或无法被作者视角收回的内容
14. **流量下注** → 按 `重仓 / 轻仓 / 观察 / 放弃` 输出，完整写作流程中由用户确认后落一份 `00_选题卡.md`
