# 内容反馈案例库（模板）

这里保存还不足以升级为全局规则、但值得复用的上下文案例。公开版不包含真实文章标题、草稿箱记录或个人反馈。

长期稳定的作者声音写入 `style-profile.md`；平台硬约束写入对应发布标准；只影响当前文章的意见不要沉淀。

## 案例格式

```markdown
### YYYY-MM-DD - 简短标题

- Stage: 发生在哪个节点
- Content type: 深度文 / 实用文
- Platform: 公众号 / 通用写作
- User feedback: 用户实际指出了什么
- Before: 修改前的最小必要片段
- After: 修改后的最小必要片段
- Why it worked: 哪个阅读或表达问题被解决
- Applies when: 适用条件
- Do not apply when: 禁用条件
- Confidence: low / medium / high
- Evidence count: 1
```

## 待验证观察

把只有一次证据的模式先放在这里。再次出现时合并证据；确认稳定后再迁移到风格画像或平台标准。

## 已接受案例

### 示例 - 把抽象开头换成可验证动作

- Stage: 编辑修改
- Content type: 实用文
- Platform: 公众号
- User feedback: 开头太像概念说明，读者不知道问题发生在哪里。
- Before: `很多团队都在面临信息过载的问题。`
- After: `周一早会刚结束，三份互相冲突的表格同时进了群。`
- Why it worked: 用可观察动作建立说话位置，再允许后文解释概念。
- Applies when: 研究材料中确实存在对应场景或记录。
- Do not apply when: 需要为场景补造人物、对白或时间细节。
- Confidence: low
- Evidence count: 1

## 已拒绝案例

记录那些看似“更有风格”但损害事实、逻辑或可读性的改法，避免同类问题反复出现。
