# 微信公众号发布标准

## 目的

定义微信公众号发布准备节点的目标、排版边界、封面约束和上传约束。

## 节点目标

该节点不是重新创作，而是把 `05_最终稿` 转成更适合微信公众号发布并直接上传草稿箱的版本：

- 更适合手机端连续阅读
- 更适合公众号正文 HTML 呈现
- 方便用户在草稿箱中手动校准并准备发布

## 排版规则

### 保持判断不变

- 不改文章立场
- 不偷偷删减关键判断
- 不重写主题结论

### 只优化呈现

- 长段拆短，减少手机端阅读压迫感
- 首段允许略强化导语感，但不能改论点
- 保留标题层级、引用、列表、代码块、图片说明
- 不根据正文关键词自动创造小标题；上传排版只转换来稿中明确存在的标题层级
- 如果来稿使用“首行标题 + 一、二、三……”的散文式结构，首行标题只作为草稿箱标题，不在正文重复渲染；首个编号小节可作为话题引入段落承接，不渲染小标题和分割线；后续中文编号小节应转成公众号分段标题
- 输出 HTML 时使用内联样式，避免依赖外部 CSS
- HTML 默认使用“历史强强调主题”，不做花哨视觉组件，但允许更明显的公众号节奏和句子强调

### 段落节奏

- 段落默认以 1 到 2 句为主，优先保证手机端一屏一口气读完
- 极长段落要拆开
- 短桥段、转折句、结论句允许单独成段
- 避免连续大段“墙式正文”

### 强强调主题规则

- 标题区弱化“商务摘要”感，不使用报告式眉标作为默认样式
- 正文内不再重复渲染文章大标题，标题以草稿箱标题为准
- 二级标题默认使用“微信可见的字符型居中短分割线（段前段后各 24px）+ 居中高亮标题”组合，分割线不要依赖空标签或纯 border，不要做满宽硬线，服务正文推进而不是企业报告感
- 如果原稿已有 `---` 且紧贴分段标题，只保留一条标题分割线，避免连续重复分割线
- 引用块默认使用明显的浅底卡片，形成阅读停顿点
- 列表、分隔线、代码块需要统一，但整体观感优先贴近公众号强节奏长文，而不是商务模板
- 保留来稿中已有的 `<text color="red">...</text>` 和 `<quote-container>...</quote-container>` 标记

### 固定排版基线

- 除分段标题外，正文、强调句、引用内文、列表项统一使用 `15px`
- 分段标题统一使用 `18px`
- 正文类行高统一使用 `28px`
- 正文类段前段后间距统一使用一套固定节奏，默认段后距为 `22px`
- 桥段句、强调句可以加粗或着色，但不再额外放大字号
- 作者尾注是显式配置项，公开默认不注入任何项目品牌

### 高亮规则

- 默认采用“显式标记优先 + 语义驱动自动识别”的混合高亮
- 优先强化：标题、引用、列表项、结论句、转折句、判断句
- 自动高亮默认比旧策略更积极，但仍需避免整篇连续刷红
- 显式红字标记应被稳定保留为强强调句
- 高亮以红色判断句、轻强调短语、引用卡片三档组合，不使用荧光色
- 默认高亮红统一使用同一套红色，不混用多套深浅红

### 可选作者尾注

- 只有配置 `WECHAT_MP_AUTHOR` 时，才在正文末尾追加“作者标识 + 互动引导”组件
- 作者标识格式为 `>/ 作者：<名称>`，左对齐，`14px`，颜色 `#b2b2b2`
- 作者标识下方使用一条浅灰细分割线；分割线后保留 `16px` 上间距再进入互动引导
- 互动引导左对齐，正文为 `15px`、`#888888`、`1.6` 行高；`赞、在看、转发` 和 `星标` 使用 `#000000`，不额外加粗
- 若来稿本身已包含完整的同一尾部，不重复追加
- 启用的作者尾注保留在最终上传的公众号 HTML 中；回读时要识别为平台尾部，不把它当成文章正文或作者文风样本

启用后的默认内容模板：

```md
>/ 作者：<你的公开作者名>

谢谢你读到最后🙇‍♂️

如果刚好让你有一点收获，不妨点个「赞、在看、转发」三连🙏

想第一时间看到下一篇，可以顺手把我设为星标⭐

有不同的想法，欢迎评论区留言💬
```

## 封面规则

- 封面可选使用本地品牌参考图 `assets/brand/reference.png`
- 提供参考图时保留角色核心识别特征
- 参考图只锁定角色识别，不锁定原图动作、姿势和表情；每篇根据文章主题设计新的动作和表情变化
- 未提供参考图时改用主题相关的通用人物、物件或场景隐喻，不虚构固定品牌角色
- 避免重复使用参考图里的托腮姿势，除非该姿势与文章主题强相关并由用户明确要求
- 封面默认采用与正文配图一致的手绘 sketchnote / visual note-taking / mind map infographic 风格，而不是泛化 3D 场景插画
- 封面默认以图像叙事为主，先用人物动作、表情、场景隐喻和少量图标表达文章核心判断，IP 形象作为讲解者或视觉锚点出现
- 构图为微信公众号超宽横版，宽高比必须为 `2.35:1`
- 执行前必须展示当前唯一生图路径、模型、尺寸、输出路径和完整 prompt，并由用户确认后再执行
- 封面生图执行统一走全局 `imagegen` skill
- 工具路径以当前全局 `imagegen` skill 为准；模型或 endpoint 未公开时如实注明由工具管理，不能伪造参数。尺寸是交付要求
- 唯一默认尺寸：`3760x1600`，精确等于 `2.35:1`；禁止使用 `3840x2160` 等 `16:9` 尺寸
- 内置生图若返回其他比例，必须先按内容安全区裁切到 `2.35:1`，再缩放到 `3760x1600`；禁止非等比拉伸
- 保存和上传前必须读取实际图片尺寸并校验。实际尺寸不是 `3760x1600` 时停止，不得以提示词里写过 `2.35:1` 代替文件验证
- 默认尽量少放文字；只在帮助理解时加入 1 个中心短语，或最多 1-2 个极短中文标签
- 封面提示词只提供最多两条极短核心句，不注入正文长摘要；文字只是可选辅助，画面应优先用人物动作、场景隐喻和图标表达主题
- 不做标题海报，不搬运大段正文，不堆密集小字，不做文字主导的知识图谱封面
- 画面服务文章主题，不做空泛角色海报

## 正文配图规则

- 公众号正文配图是草稿箱审看时选择的可选增强节点
- 配图节点只更新微信公众号草稿箱正文
- 配图直接读取当前草稿箱正文，不依赖风格回读样本
- 配图前必须先产出插图方案，包含插入位置、段落用途、视觉方向、完整 prompt、尺寸/比例建议
- 配图默认优先放在对应段落组末尾，紧贴下一小节标题或分割线之前，不要插在段落中腰
- 默认每篇 2-4 张正文图，宁少不滥
- 优先插在开头现场、核心概念/隐喻、方法步骤转折、结尾动作或结尾隐喻附近
- 避免在首段前插图、在连续短段之间频繁插图、打断情绪推进、重复封面创意
- 正文图可选使用本地品牌参考图 `assets/brand/reference.png`；提供时让品牌角色作为讲解者、观察者或视觉锚点出现
- 正文图默认方向是结合段落要点的手绘知识导图，而不是泛化场景插画、人物海报或抽象装饰图
- 每张图必须先提炼服务段落的 3-5 个核心信息，再转成中心标题、发散分支、短标签和图标
- `实用文` 优先将职场工作流、桌面/材料整理、交接单、检查清单等内容画成可执行的 mind map infographic
- `深度文` 优先将情绪现场、关键矛盾、认知反转和收束隐喻画成观点地图、张力对照图或概念关系图
- 正文图默认允许短文字标签，因为知识导图需要可读标签；标签必须短、清晰、中文可读，不得搬运大段正文
- prompt 必须包含核心风格词：`hand-drawn sketchnote style`, `visual note-taking`, `mind map infographic`, `doodles`
- prompt 必须包含媒介与材质：`marker pen texture`, `on clean white paper background`, `high quality sketch`
- prompt 必须包含布局与元素：`central main title text`, `branching arrows pointing outwards`, `cute colorful icons for each section`, `handwritten text labels`
- prompt 必须包含颜色风格：`colorful but soft`, `pastel marker colors`, `clear and legible`
- 正文图默认使用公众号友好的横图或宽图
- 所有正文图必须先上传为微信正文图片 URL，再插入草稿箱正文；不得把本地路径写入公众号 HTML
- 生图执行统一走全局 `imagegen` skill；本项目只维护插图方案、提示词、草稿箱更新和日志规则

## 上传规则

- 正文内容上传到公众号草稿箱前，正文内本地图片要先换成微信可访问 URL
- 封面通过缩略图素材接口获取 `thumb_media_id`
- 上传正文必须复用排版节点生成的 WeChat HTML，并保留已启用的作者尾注
- 草稿上传失败时，保留封面和日志，支持单独重试上传

## 风格回读边界

回读只用于学习用户在草稿箱中修改后的表述、标点、断句、分段与语气，服务于风格画像；不审查格式细节，不把回读文件作为发布或配图源。

同稿上传基线、远端样本和画像沉淀按 `docs/operations/feedback-loop.md`；命令、文件名和状态字段见 `docs/operations/wechat-publish-setup.md`。

## 产物规则

- 排版转换作为上传前的内部步骤存在，不作为主流程中的独立审看稿保留
- 草稿箱 `media_id`、封面、风格回读样本和日志保留在本地输出目录中，支持后续回读同步与重试上传
