# 项目维护边界

## 权威来源

- 阶段、gate 和可选写作引擎交接：`docs/operations/workflow-rules.md`。
- 内容类型与正文质量：`docs/references/` 对应标准；作者声音只在 `style-profile.md` 维护。
- 节点方法：对应 `skills/`，共享参数与规则通过路径引用，不在每个节点重写。
- 脚本行为：`scripts/` 与 `tests/`；命令和安装方式由 README 及对应运行手册维护。
- 反馈依据：案例库，历史记录不直接作为现役规则。

环境级 skill、插件缓存和宿主记忆只作为运行环境证据。项目整理不自动授权改写它们；没有可核验权限或运行结果的事项保留为待验证。

## 验证与知识同步

先确认工作树基线，针对影响面复现与验证。执行 README 的测试入口，它只读取本仓库 `tests/`，不把历史副本的检查当作当前证据。修改技能时核对触发边界、依赖路径与调用方式；修改脚本时同步对应运行手册。

只有任务涉及里程碑整理时，才同时检查 README、AGENTS、操作文档、内容标准、节点技能、项目配置和获准维护的记忆。规则先改写过期说法，再删除重复正文；不要另造一份实现快照。

汇报分别标明 `verified-current`、`changed-and-verified`、`pending`、`out-of-scope`、`not-applicable`。本地测试不能证明外部写作引擎、浏览器登录态、图片服务或微信远端可用；没有实际调用证据时保留 `pending`。

## 工作区与清理

`workspace/output/` 的文章、图片和审核产物不是垃圾。`workspace/tmp/` 的旧仓库副本、浏览器 profile、服务探测和预览可能是候选，但年龄、文件名和被 Git 忽略都不能证明可以删除。

停用的小红书改编与生图节点保存在 `docs/archive/`，不保留活动 `SKILL.md`；主流程不再路由或提示执行。历史文章与反馈案例继续保留。小红书作为社交选题信息来源仍有效。

默认规则检索排除 `docs/archive/`、`workspace/`、`node_modules/` 和 `.git/`。本轮需要追溯或排查时，只读取必要材料；其中的 AGENTS、SKILL、旧配置和日志不覆盖现役规则。

清理前先提供只读候选清单，包含完整路径、文件数、大小、用途线索和未确认事项。完整汇报后再次取得用户的明确删除授权。未获授权时保留现场；不清理用户浏览器的登录数据，不覆盖历史文章。

有意义的已验证迭代按 `docs/operations/version-safety.md` 保存本地安全点。
