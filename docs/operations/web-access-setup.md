# 浏览器访问配置

## 目的

当任务需要登录态、动态渲染或页面交互时，使用当前运行环境明确提供的浏览器能力，并保护用户已有会话、标签页和凭证。

本项目不绑定 Chrome、Edge、特定扩展或本机 profile。不同使用者可以选择 Codex 浏览器、Chrome 连接器或其他具备可见交互能力的浏览器表面。

## 选择浏览器表面

开始前确认：

1. 当前运行环境实际提供哪些浏览器表面；
2. 哪一个表面具备本轮所需登录态；
3. 用户是否明确指定了浏览器、profile 或账号；
4. 该表面是否允许创建独立工作标签页并在任务结束后释放。

优先使用用户明确指定、且已具备所需登录态的表面。不要读取、复制或迁移浏览器 profile、cookie、token、密码和扩展存储来制造登录态。

如果需要从首选表面切换到备用表面，先披露原因和能力差异。公开网页搜索不能静默替代登录态社交扫描。

## 连接与恢复

使用当前浏览器工具提供的只读轻量操作探测连接，例如列出标签页或读取当前页面状态。一次空列表、超时或通信中断不能证明浏览器或扩展未安装。

连接失败时：

1. 区分浏览器未运行、连接器未授权、扩展未启用、通信中断和目标页未登录；
2. 只执行当前运行环境文档支持的恢复操作；
3. 恢复仍失败时停止完整社交验证，准确报告失败层级；
4. 不通过读取凭证、复制 profile 或接管用户标签页绕过失败。

如果目标页要求登录，在当前选定的浏览器中停下并请用户自行登录。

## 内容级健康检查

平台只有同时满足以下条件才记为 `可用`：

- 页面显示目标平台的真实内容列表或详情，而不是登录页、验证码、错误页或空壳；
- 能读取至少一条候选内容；
- 能获得发布时间或等价的新鲜度字段；
- 能获得该平台适用的互动指标，如点赞、评论、收藏、转发或回答互动。

健康检查至少记录：平台、检查时间、所用浏览器表面、登录态、可提取条目数、时间字段、互动指标和状态原因。不得记录 cookie、token、密码或完整个人 profile 信息。

状态定义：

- `可用`：内容、时间和互动字段均可读取；
- `受限`：只能读取部分内容或关键字段缺失；
- `不可用`：只有登录页、验证码、错误页、空壳或连接失败。

## 来源覆盖

完整热点验证默认尝试：

- `X`
- `Zhihu`
- `Xiaohongshu`
- `Jike`
- `Weibo`

只有 `X` 可用、至少两个中文主社交平台可用、且主信源合计至少三个可用时，才能声称完成完整社交讨论验证。

如果覆盖不足，先停止并告知用户缺失来源、失败原因和结果偏差，再由用户决定是否接受缩减来源。不要自动换成公开搜索继续。

## 标签页边界

- 优先新建一个任务专用标签页，顺序访问各平台，降低内容串扰；
- 只关闭或释放本次任务创建的标签页；
- 不修改用户原有标签页、收藏、扩展、下载目录或默认浏览器设置。
