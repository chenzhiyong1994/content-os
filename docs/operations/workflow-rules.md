# 流程规则

## 执行前读取顺序

执行任何项目任务前：

1. 先读本文件
2. 再读 `docs/references/` 下相关标准
3. 再读 `skills/` 下相关项目技能
4. 然后才能执行

如果任务涉及初稿、修改稿、风格深化、审稿、最终稿或小红书改编，也读取：

- `docs/references/human-writing-standard.md`

如果任务涉及用户审核反馈、草稿箱手动校准、风格规则沉淀或 skill 迭代，也读取：

- `docs/operations/feedback-loop.md`

## 内容范围

主要领域：

- AI
- 科技
- 职场和职业发展

除非用户明确要求，否则不做：

- 娱乐八卦
- 美食
- 育儿
- 时尚
- 与核心领域无关的泛生活方式话题

## 基本原则

### 先读标准

不要凭记忆执行。每次任务开始时，都要读取相关标准。

### 先声明内容类型

在选题或研究锁定方向前，先声明：

- `内容类型`：`深度文` 或 `实用文`
- `目标受众`：`上班族` / `普通人` / `管理者`
- `文章目标`：`建立认知` / `立即上手` / `推动流程改造`

内容类型路由以 `docs/references/content-type-standard.md` 为准。

不要让下游节点根据正文自行猜内容类型。

### 保持稳定流程

默认阶段顺序和产物只以本表为准：

| 顺序 | 阶段 | 本地产物 |
| --- | --- | --- |
| 前置 | 热点收集（可选） | `00_选题卡.md`（进入完整写作流程时） |
| 1 | 研究素材 | `01_研究素材.md` |
| 2 | 微信公众号初稿 | `02_初稿.md` |
| 3 | 编辑修改 | `03_修改稿.md` |
| 4 | 风格深化（必做） | `04_风格深化.md` |
| 5 | 最终稿 | `05_最终稿.md` |
| 6 | 微信公众号发布准备 | 发布资产和日志 |
| 7 | 待发布源稿回读 | `reviewed-source/reviewed-source.md` 和 `.html` |
| 8 | 公众号正文配图（可选） | 配图方案、图片和更新日志 |
| 9 | 小红书适配 | `06_小红书版.md` |
| 10 | 小红书图片生成 | 小红书图片和日志 |

热点收集只能作为可选前置节点，发生在研究前。

AI 话题可以先通过 `skills/aihot-signal/SKILL.md` 获取快速信号，再由热点收集完成社交讨论验证和流量判断。AI HOT 聚合摘要不是研究证据，不得绕过原文核验。

两个内容类型共用同一阶段顺序。差异体现在部分节点的执行方法，不体现在流程顺序。

`simulated-critique` 不再是稳定流程节点。事实、来源、逻辑、AI 惯用句和已知风格问题的机器检查，分别内嵌在 `03_修改稿` 和 `05_最终稿` 的生成与验证中。只有用户明确要求“单独审稿”“挑毛病”或“先不要改”时，才按需调用该 skill。

`04_风格深化` 每篇必做。必做的是风格审视、候选生成和前后比较，不是结构性重写。它先保护 `03_修改稿` 已经成立的作者声音、论证骨架、事实精度和阅读节奏，再按真实缺口选择保留、局部深化或结构重构。改动幅度不是质量指标；没有净收益时，允许把 `03_修改稿` 原文保存为 `04_风格深化.md`。具体判断按 `skills/style-refine/SKILL.md` 执行。

可选节点仍然是明确检查点。不要把 `optional` 理解成执行者可以静默跳过。

完成待发布源稿回读后，必须停在公众号正文配图检查点，询问用户是生成配图方案，还是跳过进入小红书。

### Gate 语义

项目只使用四种 gate：

- `Review Gate`：本地阶段产物保存后的内容审看。
- `Choice Gate`：用户选择执行或跳过可选节点。
- `External Gate`：用户确认外部发布或更新动作。
- `Paid Gate`：用户确认付费图片生成请求。

用户在 gate 处回复 `继续`、`确认`、`可以`、`按这个走`、`下一步` 等，含义是：执行下一个可执行节点。除非用户要求复述，不要重复已经确认的方案。

如果用户在 `Review Gate` 要求修改，就修改当前产物并回到同一个 gate。如果用户改变路线，就更新路线并从合适节点继续。

可选节点回复规则固定：

- `跳过`、`不用`、`不需要`、`继续小红书`：跳过可选节点，进入小红书适配。
- `做`、`生成`、`配图` 或同义表达：执行可选节点规划，然后停在对应的 `Paid Gate` 或 `External Gate`。
- 模糊回复：只问一个简短澄清问题。

### Review Gate 交付格式

每个稳定内容阶段保存本地产物后，都必须停在 `Review Gate`。交付信息包含：

- 本地产物路径
- 本阶段变化或决策摘要
- 阶段对应审看面：
  - 研究素材：选题方向、核心发现、事实边界、来源列表
  - 初稿、修改稿、风格深化、最终稿、小红书版：标题、开头样段、结尾样段、结构或风格自检
  - 发布准备、待发布源稿回读、正文配图、图片生成：计划动作、外部副作用、资产或图片生成路径
- 建议的下一阶段

不要在没有阶段确认的情况下端到端跑完整流程。

### 可选外部写作引擎

以下写作重节点默认由当前编排 Agent 按对应 skill 执行：

- `02_初稿`
- `04_风格深化`
- `05_最终稿`
- `06_小红书版`

节点执行仍读取对应项目 skill。`03_修改稿` 使用 `skills/wechat-revise/SKILL.md`，`04_风格深化` 使用 `skills/style-refine/SKILL.md`，`05_最终稿` 使用 `skills/wechat-finalize/SKILL.md`。

如果使用者希望把上述节点交给另一个本地 CLI，可以同时配置：

- `CONTENT_OS_WRITER_COMMAND`：可执行命令或适配器入口
- `CONTENT_OS_WRITER_MODEL`：完整、固定的模型标识

两项都未配置时，保持公开默认行为，由当前编排 Agent 写作。只配置一项时，停在当前节点并说明缺少的配置，不要猜测命令、模型或本机默认值。

使用外部写作引擎时，当前编排 Agent 准备来源上下文、路线元数据、相关规则和精确任务提示词。具体适配器必须使用非交互模式，并把 `CONTENT_OS_WRITER_MODEL` 作为显式模型参数传入；命令行参数格式以使用者选择的引擎为准。

当前编排 Agent 始终负责校验返回文本、执行节点验证，并把通过的内容保存为本地产物。

对于初稿和风格深化等创作型交接，不要把事实边界清单、审稿规则、AI 味检查、发布限制或禁止项塞满写作提示词。给来源产物、共同风格内核和用户提供的代表作语料库，让写作引擎先写，再由当前编排 Agent 在节点后置验证中做事实与质量检查。

风格深化交接必须同时说明本轮真实风格缺口、必须保护的原稿资产和最小可行改动幅度。不得用“不能只是润色”“必须明显重写”等要求迫使写作引擎制造差异；候选稿是否采纳只看相对 `03_修改稿` 的净收益。

用户提供的代表作属于同一种作者文风，是一个不可按题材拆分的校准语料库。不要每次只挑一篇临时模仿。`docs/references/style-profile.md` 负责把代表作中反复出现的叙述运动、材料组织、句法节奏和判断生成方式编译成共同风格内核。起稿前联合阅读全部代表作，是为了校准内核在真实文本中的力度和尺度，不在每篇文章里重新发明一套风格总结。

题材只能决定本次文章更强调共同风格内核中的哪一部分，例如技术考古、现实摩擦、人文思辨或情感余波，不能改变作者声音。`02_初稿` 与 `04_风格深化` 必须使用同一套共同内核，防止两次写作变成两种人。

代表作原文共同定义作者声音的边界，`style-profile.md` 是代表作语料与用户稳定反馈的编译结果。写作提示词可以传入代表作原文，但不要再同时塞入完整迭代记录和详细检查清单。

`docs/references/style-profile.md` 当前明确生效的少量正文规则可以随节点任务交给写作引擎；模板占位符不能当作规则。写作提示词还可以加入 `docs/references/human-writing-standard.md` 的三句正向罗盘：从可追溯材料和明确说话位置出发；每段增加事实、动作、例子、区别、后果或诚实的不确定性；先让主语和动作出现。不要把完整活人感标准或审稿清单一并塞入。

如果外部写作引擎不可用或调用失败，停在当前节点并报告错误。不要删除显式模型参数重试、擅自换模型或静默切回当前 Agent 代写。

外部写作引擎只是可选的窄范围执行交接。其他节点保持既有执行方式，除非用户明确要求改变。

### 本地阶段产物必须保存

每个稳定内容阶段完成后，必须立刻保存本地产物。不要只依赖长对话上下文。

默认产物位置：

- 完整写作流程中的已确认选题：`workspace/output/YYYY-MM-DD_<article-slug>/00_选题卡.md`
- 稳定文本阶段：`workspace/output/YYYY-MM-DD_<article-slug>/<stage-number>_<stage-name>.md`
- 微信公众号发布准备：公众号草稿箱结果、本地日志和资产
- 待发布源稿回读：本地 `reviewed-source.html` 和 `reviewed-source.md`
- 图片生成阶段：`workspace/output/` 下对应输出目录

新产物必须使用上表编号。文件编号和阶段顺序必须一致。

### 外部动作和付费动作

不要静默触发外部发布、草稿箱更新或付费图片生成。

每次图片生成请求前必须展示：

- 唯一活动生图路径
- 模型、接口归属方、尺寸、输出路径、完整 prompt
- 等用户明确确认后再发起付费外部请求
- 不要提供或静默使用旧图片通道

微信公众号草稿上传或草稿箱更新前，必须展示动作、目标草稿或账号界面、预期本地日志/资产，以及需要用户审看的步骤。

### 全局规划规则的适用范围

日常内容生产节点直接按本流程执行。不要为日常内容阶段额外增加设计文档或额外确认点。

只有修改流程规则、项目技能、脚本或架构时，才使用更重的设计/规划流程。

### 展示技能规则改动

如果修改项目 skill 或规则文件，最终回复必须列出具体改动。

### 保持根目录干净

使用：

- `workspace/tmp/`：临时笔记和中间文件
- `workspace/output/`：生成产物
- `assets/`：稳定视觉参考

## 浏览器自动化规则

需要登录态或动态网页操作的平台，默认使用环境提供的 `web-access` 能力。

环境设置见 `docs/operations/web-access-setup.md`。

项目热点收集默认规则：

- 社交验证使用用户明确指定、且具备本轮登录态的浏览器表面；项目不绑定浏览器品牌、扩展或本机 profile
- 一次浏览器枚举为空、连接失败或通信中断都不能证明浏览器能力不可用；必须按失败层级准确报告
- 切换到备用浏览器表面前必须披露原因和能力差异，不得静默替换登录态
- 开始采集前按 `docs/operations/web-access-setup.md` 对每个主信源执行内容级健康检查
- HTTP 200、登录页、验证码、错误页或空页面壳都不算数据可用
- 完整验证必须覆盖 `X` 和至少两个中文主社交平台，且五个主信源都要记录 `可用 / 受限 / 不可用`
- 不要静默把登录态社交平台扫描替换成公开网页搜索
- 如果浏览器登录态或主社交扫描降级，先停止并告知用户，再决定是否用缩减来源继续

## 微信公众号发布准备规则

到达微信公众号发布准备时，使用 `skills/wechat-publish-prep/SKILL.md`，并应用 `docs/references/wechat-publishing-standard.md`。

如果用户在公众号草稿箱手动编辑后继续下游：

- 等用户明确表示已经编辑完成
- 根据 `draft_media_id` 回读远端草稿正文
- 将待发布源稿与上传前最终稿对比；如果用户做了实质标题、措辞、节奏、结构或删减修改，先通过 `style-feedback` 执行反馈闭环：修正下游来源、分类差异，并按需更新风格画像、案例库或相关 skill
- 把待发布源稿保存为下游标准来源
- 小红书适配使用待发布源稿，不使用上传前本地最终稿

如果用户想在待发布源稿回读后添加公众号正文配图：

- 使用 `skills/wechat-article-illustration/SKILL.md`
- 先基于待发布源稿生成配图方案
- 展示活动生图路径、模型、图片数量、插入位置、输出路径和完整 prompts
- 等用户明确确认后再调用 `imagegen`
- 只更新微信公众号草稿箱正文，不把带图 HTML 喂给小红书适配

如果用户还没说是否执行正文配图，在进入小红书适配前只问一次。只有用户明确跳过配图或确认不需要配图后，才继续小红书。

该节点环境和凭证设置见 `docs/operations/wechat-publish-setup.md`。

## 热点收集规则

如果任务从选题发现开始，使用 `skills/social-hotspot-collector/SKILL.md`，并先应用 `docs/references/hotspot-collection-standard.md` 的新鲜度和讨论规则。

AI 话题先使用 `skills/aihot-signal/SKILL.md` 建立快速候选池，再通过默认社交扫描验证真实讨论、饱和度和流量潜力。AI HOT 不替代登录态社交扫描；如果用户只要一份快速 AI 资讯列表，可以单独使用该 skill，不启动完整热点流程。

如果选题发现属于完整写作流程的一部分，进入研究前要根据声明的内容类型筛选候选：

- `深度文`：优先有张力、摩擦和判断空间的话题
- `实用文`：优先具体场景、低成本尝试路径和明确任务结果

输出按 `重仓 / 轻仓 / 观察 / 放弃` 给出流量下注。完整写作流程中，用户确认候选后只保存一份轻量 `00_选题卡.md`，研究节点直接消费它；不要制作跨项目交付材料包。

默认来源覆盖：

- 主社交扫描：`X / Zhihu / Xiaohongshu / Jike / Weibo`
- 定向账号搜索（可选）：仅在本地存在 `docs/references/source-watchlist.md` 时使用其中公开信源；仓库不内置个人关注列表
- 二级补充：`Reddit / V2EX`
- 公开搜索只作为社交扫描后的补充，或在明确告知用户降级后使用

## 失败响应

如果还没读取相关标准就开始执行：

1. 停止
2. 读取缺失标准
3. 重新评估计划
4. 告诉用户漏读了什么，以及计划是否变化
