# 社交热点收集

## 先读

- `docs/operations/workflow-rules.md`
- `docs/references/hotspot-collection-standard.md`
- AI 话题还读取 `skills/aihot-signal/SKILL.md`

## 核心职责

收集值得写的候选话题，并按以下信号筛选：

- AI HOT 的近期聚合信号
- 新鲜度
- 讨论信号
- 话题饱和度和剩余时间窗口
- 题型范围
- 推荐流潜力
- 与账号写作视角的匹配度
- AI 创作者、机构、研究者和实践型账号的定向信号
- 海外文章、论文、演讲、newsletter 和研究报告中的专家信源信号

本 skill 只做选题发现，不做完整研究，也不写正文。

AI HOT 用于快速发现，不是事实终点。它的摘要、selected 状态和 score 不能替代原文核验、社交讨论信号或本项目的流量判断。

## 范围

选题发现使用两类选题轨道和一类专家信源。

### 主线题

- AI
- 科技
- 与科技相关的创业和产品变化
- 职场和职业发展
- 学习和技能形成
- 组织和管理变化
- 创作者经济和个人生产系统
- 平台规则和推荐机制
- AI 时代的判断力、注意力和决策变化

### 流量实验题

更宽泛的话题可以作为 `流量实验题` 进入，但必须能拉回普通人的工作、学习、平台、技术或社会变化压力。例子：

- 教育和学习焦虑
- 消费和效率幻觉
- 情感生活和现代压力
- 普通人身边的社会变化
- 媒介习惯和平台讨论模式

### 专家信源候选

海外专家文章、论文、演讲、newsletter 和研究报告可以作为 `专家信源候选`。不要默认全文翻译，要提炼、概括、补充中文语境并评论。

除非用户明确要求，否则避开无关生活方式或娱乐话题。

## 平台规则

目标平台需要登录态或动态渲染时，使用环境提供的 `web-access` 能力。

使用用户明确指定、且具备本轮登录态的浏览器表面。项目不绑定浏览器品牌、扩展或本机 profile，也不要用纯公开网页搜索替代尚未完成的社交扫描。

## 必要前置检查

AI 话题先使用 `aihot-signal` 做一次快速扫描。它不需要登录态浏览器。

继续执行完整热点收集前必须：

1. 按 `docs/operations/web-access-setup.md` 选择浏览器表面并完成运行环境支持的轻量连接探测。
2. 不得因一次空列表、超时或通信通道关闭就声称浏览器能力未安装；恢复失败时准确报告失败层级。
3. 依次打开 `X / Zhihu / Xiaohongshu / Jike / Weibo` 的目标搜索、热榜或信息流页面。
4. 按 `docs/operations/web-access-setup.md` 检查登录态、内容列表、发布时间/新鲜度字段和互动指标。
5. 为每个平台记录 `可用 / 受限 / 不可用`；达到主信源覆盖门槛后才能开始正式评分。

HTTP 200、页面标题存在或客户端页面壳不算通过。如果登录受阻，请用户在当前选定的浏览器中登录；如果覆盖门槛未满足，停止并说明降级点，不要静默用公开搜索继续。

## 默认来源覆盖

快速 AI 信号：

- 使用 `skills/aihot-signal/SKILL.md`
- 宽泛扫描默认读取精选条目；用户要求日报、全量或关键词时按该 skill 路由
- 保留原文 URL 和 AI HOT 条目 URL，候选进入研究前回到原文核验

主社交扫描：

- `X / Zhihu / Xiaohongshu / Jike / Weibo`

定向账号搜索（可选）：

- 仅在本地存在 `docs/references/source-watchlist.md` 时执行；仓库不内置维护者的个人账号池
- 在主社交扫描之后、二级补充之前执行
- 重点找工具、工作流、提示词、教程、方法和实践型 AI 用法

二级补充：

- `Reddit / V2EX`

公开网页搜索：

- 只用于补充发现、交叉验证，或明确声明的降级运行
- 当登录态社交平台在范围内时，不得作为唯一默认输入

## 来源健康状态

热点结果先给出本轮来源健康摘要：平台、检查时间、登录态、内容列表是否可见、可提取条目数、发布时间/新鲜度字段、互动指标和 `可用 / 受限 / 不可用` 状态。

完整社交讨论验证要求：五个主信源都已尝试，`X` 可用，至少两个中文主社交平台可用，且主信源合计至少三个可用。受限来源可以提供线索，但不得计入完整覆盖，也不得用其他平台的指标替代。

## 输出格式

结果按 `重仓 / 轻仓 / 观察 / 放弃` 分组。`重仓` 和 `轻仓` 是可以进入用户选择的候选，`观察` 和 `放弃` 用于解释为什么暂不投入。

每个入选候选输出：

- 标题或短选题标签
- 题型：`主线题` / `流量实验题` / `专家信源候选`
- 推荐内容类型：`深度文` / `实用文`
- 目标受众匹配度
- 为什么重要
- 新鲜度信号
- 长尾信号，如适用
- 讨论信号
- 定向账号信号，如适用
- 专家信源信号，如适用
- 实用价值信号，如适用
- 推荐流假设
- 流量下注和读者钩子
- 时间窗口和话题饱和度
- 反向风险
- 推荐潜力、痛感、长尾价值、作者适配度、来源可靠性、收藏/转发理由和账号风险评分说明
- 后续研究角度
- 来源链接或平台线索

如果该次选题发现属于完整写作流程，用户确认某个候选后，把最小交接信息保存为同一文章目录下的 `00_选题卡.md`：

- route metadata：内容类型 / 目标受众 / 文章目标
- 选题与一句话判断
- 题型和下注等级
- 读者钩子、推荐流假设、时间窗口、饱和度、反向风险
- 候选来源指针和待核验项
- 下一步研究问题

不要在选题卡中扩写研究素材、正文大纲或成稿表达，也不要再制作跨项目 handoff 或材料包。独立选题查询无需强制保存文件。

## 筛选规则

### 新鲜度

遵守 `docs/references/hotspot-collection-standard.md`。

不要因为一个旧话题看起来重要，就保留它。

### 讨论质量

优先真实讨论，而不是孤立公告。

信号包括：

- 多个账号或社区讨论同一件事
- 回复、评论、转发或点赞
- 最近窗口内持续讨论
- 可信定向账号独立提到同一工具、工作流或方法

### 实用价值

定向账号结果优先保留内容创作者或知识工作者能快速使用的东西。

优先级：

1. 工具、应用、教程、提示词模板、工作流技巧
2. 可复用 AI 使用方法、内容工作流、效率技巧、技能建设框架
3. 能改变读者实践型 AI 认知的专家洞察

排除主要是基础设施新闻、安全专家内容、没有应用路径的论文、B2B 公告、融资营收新闻或纯 benchmark 对比的定向账号内容。

### 题型和推荐潜力

每个候选必须标记为：

- `主线题`
- `流量实验题`
- `专家信源候选`

评估：

- 非关注者能否快速理解并在意
- 是否触及普通人或职场真实痛点
- 是否有长尾价值
- 是否能从具体场景长出判断
- 来源是否足够支撑研究
- 读者是否有收藏或分享理由
- 是否稀释账号辨识度

不要只按热度排序。

### 相关性

即使话题很热，只要不服务本项目内容方向，就排除。

`流量实验题` 可以略超出常规范围，但必须能用账号视角写。如果角度不能拉回工作、学习、技术、平台压力或普通人生活变化，就排除。

`专家信源候选` 如果没有中文读者语境、没有普通人含义、没有清晰文章角度，就排除。

## 流程

1. AI 话题先用 `aihot-signal` 建立快速候选池。
2. 主动建立所选浏览器表面的连接，再对五个主信源执行内容级健康检查并记录状态。
3. 判断本次是只收主线题，还是主线题和流量实验题双轨。默认双轨，除非用户要求收窄。
4. 扫描主要登录态社交平台。
5. 如果存在本地观察列表，使用其中公开信源和实用价值关键词做定向账号搜索。
6. 需要时加入专家信源发现。
7. 用 `Reddit / V2EX` 做二级验证和补充。
8. 标记 `主线题`、`流量实验题` 或 `专家信源候选`。
9. 按新鲜度、持续再讨论和话题饱和度过滤。
10. 按讨论信号或专家权威信号过滤。
11. 评分推荐流潜力、痛感、长尾价值、作者适配度、来源可靠性、收藏/转发理由和账号风险。
12. 按实用价值筛定向账号结果，按中文读者相关性筛专家信源。
13. 综合读者钩子、时间窗口、饱和度和反向风险，给出 `重仓 / 轻仓 / 观察 / 放弃`。
14. 返回分组后的短候选列表和建议下一步；完整写作流程中，用户确认后保存 `00_选题卡.md`。
