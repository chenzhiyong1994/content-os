# 微信公众号最终稿

## 先读

- `docs/operations/workflow-rules.md`
- `docs/references/content-type-standard.md`
- `docs/references/human-writing-standard.md`
- `docs/references/style-profile.md`

## 核心职责

把风格深化稿收束为可进入公众号发布准备的最终正文。

这一步不是再做一次自由风格重写。默认保留已经成立的具体材料、独特判断、自然停顿和作者气口，只修改用户指出的问题、机器能够确认的问题以及修改后连带受影响的段落。

一句话标准：

> 该修的修透，已经活着的地方别磨平。

## 输入

必选：

- route metadata
- `01_研究素材.md`
- `04_风格深化.md`

可选：

- 用户在 Review Gate 的补充反馈
- 前序版本中需要恢复的事实或表达

## 修改边界

- 先处理用户明确反馈，再处理有研究材料或规则可以证明的机器检查问题
- 不新增研究材料无法支持的事实、场景、原话、数字或因果
- 不无故新增主论点；确需新增事实时退回研究或明确补证
- 不把自然的长短变化修成等长段落和统一短句
- 不为了“更完整”恢复已经删掉的解释链
- 不用新金句覆盖原文中更朴素但有材料的判断
- 实用文必须保住最小可执行动作和可见结果

## 改稿顺序

1. 标出原稿中最该保护的段落：具体材料、知识来路、独特判断、自然停顿
2. 逐项处理用户反馈，记录每项是否已解决
3. 按 `human-writing-standard.md` 检查说话位置和逐段推进
4. 核对研究材料、事实身份、引语、数字和因果边界
5. 检查 `style-profile.md` 的当前生效的正文规则
6. 压缩重复解释、表演性中文和已经结束后的尾巴
7. 最后筛选标题，确认传播力没有改写事实

## 写作执行

本节点默认由当前编排 Agent 完成实际最终稿修改。

如使用者显式配置外部写作引擎，模型、调用命令和失败处理只以 `docs/operations/workflow-rules.md` 的“可选外部写作引擎”为准。本 skill 不保存任何维护者专属命令或模型值。

当前编排 Agent 准备提示词，包含：

- `04_风格深化` 全文
- 研究材料和 route metadata
- 用户补充反馈
- `human-writing-standard.md` 的三句正向罗盘
- `style-profile.md` 的当前生效的正文规则
- 本地产物目标

默认把 `04_风格深化` 作为唯一声音锚点，不再重新加载代表作样文，避免终稿阶段开启第二次风格生成。只有用户明确指出整体风格漂移并要求大幅重写时，才把全部代表作作为一个共同语料库再次放进写作提示词。

不要把完整审稿清单、发布排版规则或所有禁用词塞进写作提示词。写作执行先按用户反馈收束，当前编排 Agent 再执行逐项校验。

Prompt intent：

> 请根据用户反馈收束这份风格深化稿。优先保护原稿中已经成立的具体材料、作者判断、人文连接和自然节奏，只修改确有问题的部分。不要重新发明整篇文风，不要新增研究材料无法支持的内容。

## 验证

保存前检查：

- 用户明确反馈是否逐项解决
- 核心事实、引语、数字和因果是否仍受研究材料支持
- 具体研究首次出现时是否交代机构或作者、准确时间和研究课题
- 作者说话位置是否清楚
- 每段是否带来新东西，是否存在换说法式注水
- 具体材料和独特判断是否被过度润色磨掉
- 标题是否准确且具传播力
- 深度文的判断是否仍由材料和现实后果托住
- 是否残留素材点名式开头、模糊研究背书或已知模型惯用表达
- 人文连接是否仍在解释事实，情感高点是否仍由前文材料支付
- 实用文的行动路径是否一眼可见
- 当前生效的正文规则是否满足

## 输出

- 保存为当前文章目录下的 `05_最终稿.md`
- 提供标题、开头样段、结尾样段和结构或风格自检
- 停在 `Review Gate`
- 用户确认后再进入 `wechat-publish-prep`
