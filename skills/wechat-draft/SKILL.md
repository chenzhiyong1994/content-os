# 微信公众号初稿

## 先读

- `docs/operations/workflow-rules.md`
- `docs/references/content-type-standard.md`
- `docs/references/human-writing-standard.md`
- `docs/references/style-profile.md`

然后完整读取 `docs/references/style-examples/` 中用户提供的全部代表作，把它们作为同一种文风的共同语料库。目录里只有 README 或作者画像仍是空模板时，先请用户补充材料。

## 核心职责

把已确认的话题和素材整理成公众号初稿。

初稿不再只是“中性结构稿”。它从第一版开始就使用代表作中反复出现的叙述运动，有入口、有判断、有语境、有情绪余味。但它仍然是初稿，目标是把文章的主心骨和作者声音一起立住，让后续风格深化有东西可加深。

活人感先来自材料、说话位置和推进。口头禅、短句和情绪标点只能帮助成稿呼吸，不能替代这三件事。

一句话标准：

> 有骨架，但不要像提纲；有风格，但不要为了风格跑题。

## 输入

必选：

- 确认的话题或核心论点
- 素材摘要 / research_rows / 用户提供的散乱想法
- 内容类型：`深度文` / `实用文`

可选：

- 大纲结构
- 用户提供的风格方向

## 起稿立场

初稿阶段联合阅读全部代表作样文，但不要按题材挑一篇模仿，也不要机械模仿格式。

要学的是：

- 怎么从一个现象进入更深的处境。
- 怎么用具体事实带出判断。
- 怎么在材料、文化语境和个人体感之间来回移动。
- 怎么让文章最后留下余味，而不是只完成说明。

不要让“结构清晰”变成“报告味”。骨架应该藏在文章内部，而不是把正文写成一串规整小节。

## 起稿前材料门槛

读取 `01_研究素材` 的可写材料清单。目标为一千二百字以上的长文时，在内部确认至少五件可追溯的具体材料，并确认它们能组成一条真实过程、关系或冲突。

材料不足时不要开始长稿：

- 有公开资料可补，退回研究节点
- 依赖用户私人经历，一次最多询问三个问题
- 无法补充，缩小主题或缩短篇幅

不要用比喻、抽象后果、同义改写或模型临时想出的典型场景补足材料数量。

## 第一稿正向罗盘

动笔前在内部确定谁在说、凭什么知道、哪条材料改变了判断，以及读者读完上一段后会问什么。

写作时只带三句正向罗盘：

1. 从可追溯材料和明确说话位置出发
2. 每个新段落增加事实、动作、例子、区别、后果或诚实的不确定性
3. 先让主语和动作出现，再接时间、原因、条件和联想

详细 AI 痕迹和硬规则扫描留到初稿完成后，不要让检查清单接管第一稿。

## 先确认路线

先确认这一稿是：

- `深度文`：重点回答“这件事到底该怎么看”
- `实用文`：重点回答“这件事到底该怎么上手”

## 深度文起稿

深度文可以更自由地靠近参考样文。

起笔可以来自：

- 材料里真实存在的数字、价格、截图、动作、原话或反差。
- 一个可核验的技术、商业、文化背景。
- 一个足够刺痛的判断。

不要为了“有画面”杜撰居民会、办公室对话、家庭争吵、街边公告等无来源场景。没有真实现场时，直接从事实或判断进入，反而更干净。

推进可以不那么工整。允许回溯、插入语境、突然转弯、长段落和慢铺陈。只要最后能把现象、冲突和人的处境连起来，就算成立。

## 实用文起稿

实用文也要有作者感，但读者必须知道自己能做什么。

可以把参考样文的力量放在：

- 开头的进入方式。
- 问题被重新解释的转折。
- 方法背后的现实判断。
- 结尾的余味。

中段的步骤、示例和边界要清楚，不要被抒情冲散。

## 最小边界

写初稿时保留这些底线：

- 不编造材料里没有的具体事实、人物、对话、数据或场景。
- 不偏离用户确认的主题。
- 不直接复写参考样文。
- 不用空泛 AI 腔冒充判断。
- 实用文不能牺牲行动路径。
- 禁用冒号和破折号，改用逗号、句号或自然断句。
- 非方法论文章原则上不加小标题，依靠转场和叙事推进。
- 使用 8–10 种不同口语表达，至少三处关键短句独立成段，并至少使用一种情绪标点或口语打断。
- 至少完成一次有素材支撑的外部连接，落向文化、历史、技术或普通人处境，不硬凑典故。

当前生效的正文规则保留为成稿校验。起稿时只需知道边界，不按固定间隔插入口语、短句和情绪标点。

除此之外，允许文章按照材料自身的关系自由推进。

## 写作执行

本节点默认由当前编排 Agent 完成实际初稿写作。

如使用者显式配置外部写作引擎，模型、调用命令和失败处理只以 `docs/operations/workflow-rules.md` 的“可选外部写作引擎”为准。本 skill 不保存任何维护者专属命令或模型值。

当前编排 Agent 准备提示词，包含：

- `01_研究素材.md` 与 route metadata
- 已确认主题、核心张力和事实边界
- 代表作样文全文，作为一个共同语料库，不给单篇设置更高权重
- `style-profile.md` 的共同风格内核和当前明确生效的正文规则
- `human-writing-standard.md` 的三句正向罗盘
- 本地产物目标 `02_初稿.md`

写作提示词以 `style-profile.md` 已编译的共同风格内核为稳定基线，再用全部代表作共同校准实际语感。不要要求模型为本篇重新发明风格总结，也不要在正文中复刻样文题材、专有比喻和标志性句子。

不要同时传入完整迭代记录、详细 AI 痕迹清单和发布排版规则。写作执行完成后，当前编排 Agent 执行事实、来源、结构和已知高敏感表达校验。

## 输出格式

- 保存完整正文为当前文章目录下的 `02_初稿.md`
- 停在 `Review Gate`
- 同时简要说明内容类型、切入角度、核心判断，以及后续风格深化最值得加重的方向

## 流程

1. **理解话题**：确认核心张力。
2. **确认路由**：深度文还是实用文。
3. **读取共同语料**：完整读全部代表作原文，用它们共同校准既有风格内核，不按题材拆成不同风格。
4. **检查材料门槛**：确认目标篇幅有足够具体材料托住。
5. **确定说话位置**：明确作者凭什么知道、判断从哪里来、边界在哪里。
6. **组织素材**：
   - `深度文`：按现象、冲突、语境、人的处境分类。
   - `实用文`：按场景、卡点、动作、边界分类。
7. **确定入口**：选一个真实、有力、不一定最工整的入口。
8. **生成初稿**：由当前 Agent 或已配置的外部写作引擎写成文章，不写成提纲；每段都要比上一段多带来一件东西。
9. **自我检查**：
   - 主题是否准确？
   - 有没有伪造具体事实？
   - 有没有报告味或模板味？
   - 是否持续体现代表作中反复出现的叙述运动，而不是只在一处做风格表演？
   - 作者说话位置是否清楚，每段是否带来新事实、动作、区别或后果？
   - 是否满足 `style-profile.md` 的当前生效的正文规则？
   - 如果是实用文，读者是否知道可以怎么做？
10. **输出**：初稿正文 + 简要执行说明；不展示内部材料计数表和说话位置问答。

## 与 `style-refine` 的关系

`wechat-draft` 生成的是已经建立作者声音的初稿，`style-refine` 在此基础上进一步加深叙述密度、人文连接和情感余味。

初稿阶段不必完美模仿样文，但不能再退回完全中性的结构稿。
