# 微信公众号发布准备

## 先读

- `docs/operations/workflow-rules.md`：阶段、gate 与授权范围。
- `docs/references/wechat-publishing-standard.md`：排版、封面和风格回读边界。
- `docs/operations/wechat-publish-setup.md`：命令、配置与产物契约。
- 草稿箱人工校准完成后，读取 `docs/operations/feedback-loop.md`。

## 职责与输入

以本篇 `05_最终稿.md` 为输入，完成本地排版、封面交接和草稿箱准备。只优化发布呈现，保留主题、事实和判断。使用 `assets/brand/reference.png` 作为封面角色锚点，微信凭证按运行手册读取。

本 skill 不重复维护字体、尾注、尺寸、图片接口或模型配置。排版与封面规格直接使用发布标准；实际生图按当前全局 `imagegen` skill 执行，项目脚本只准备 prompt 和检查交付文件。

## 执行顺序

1. 运行 `confirm-summary` 和 `typeset`，先准备可审看的具体结果。
2. 展示标题、排版预览路径、目标账号或草稿界面、封面完整 prompt、参考图、实际工具路径、模型可见性、最终尺寸和资产/日志路径。
3. 核对已有授权是否覆盖本次生图和草稿上传。缺少的授权按流程 gate 获取；已经批准的具体方案不重复询问。
4. 调用全局 `imagegen` 生成封面，复制到文章资产目录并检查视觉、实际 PNG 尺寸与比例。不得执行已停用的项目 `generate-cover` 动作。
5. 用 `upload-draft -CoverImagePath "<verified-cover.png>"` 上传。上传已审看的 HTML 时显式传 `-HtmlPath`，核对其中本地图片相对路径。正式上传前可按运行手册做 `-DryRun`。
6. 保存返回的 `draft_media_id` 和日志，停在 `Review Gate`，让用户到草稿箱查看和校准。
7. 草稿箱审看时按流程核对正文配图选择；选择配图时交给 `wechat-article-illustration`，完成或跳过后结束本次生产流程。

用户明确表示手动编辑完成后，按 `draft_media_id` 执行 `sync-reviewed-source`，交给 `style-feedback` 学习表述与断句。该反馈支线不审看格式、不改写草稿，也不是配图的前置条件。

排版是本节点内部步骤，不新增独立内容阶段。用户只要 HTML 时，完成 `typeset` 并交付预览即可；该请求不授权生成封面或上传。

## 校验与失败处理

- 终稿来源、排版和封面任一未就绪，不上传；参考图为可选，缺失时披露并采用通用视觉方案。
- 作者读取 `WECHAT_MP_AUTHOR`；未配置时留空且不注入作者尾注。
- 图片工具的模型或 endpoint 未公开时如实说明，不伪造参数，不沿用历史第三方配置。
- 封面与正文图片分开处理；本地正文图先上传为微信 URL，不能把本地路径直接发到草稿箱。
- 上传成功必须保存可用的 `draft_media_id`。响应不确定时先查草稿箱和日志，再重试。
- 回读保存文字样本、同稿上传文本基线与原始 HTML 留档；实际路径和基线状态以命令返回值为准。只保留可读文字、标点、换行与分段，不重建排版格式。
- 自动小标题按上传记录识别；人工改写或来源不明的标题保留给差异审查，不据此改变正文结构规则。
- `dry-run/` 只供验证，不得用于风格学习。
- 回读失败只暂停风格学习，不得用旧终稿冒充人工修改样本。

## 交付

按 Review Gate 交付实际资产、日志、草稿标识、用户待审动作和下一节点。正式产物与试运行目录以运行手册为准，不从文件名猜测同步状态。
