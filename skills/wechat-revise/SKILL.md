# 微信公众号修改稿

## 先读

- `docs/operations/workflow-rules.md`
- `docs/references/content-type-standard.md`
- `docs/references/human-writing-standard.md`
- `docs/references/style-profile.md`

## 核心职责

直接编辑初稿，形成可交给 `style-refine` 做必做风格深化的稳定修改稿。

这一步优先解决材料、来源、结构、逻辑和推进问题，并内嵌机器能够可靠完成的检查。它不模拟挑剔读者，也不替用户判断“像不像本人”。修改后应该更扎实，但不能退回平整的匿名稿。

一句话标准：

> 先把文章站稳，不把它修成一篇平整的匿名稿。

## 输入

必选：

- route metadata
- `01_研究素材.md`
- `02_初稿.md`

可选：

- 用户在 Review Gate 的补充反馈
- 用户明确要求保留或删除的段落

## 修改边界

- 用户明确指出的问题优先处理；机器检查发现的问题只有在证据充分时才修改
- 材料不足时退回研究补证或缩短，不靠解释、比喻和典型场景补长度
- 不新增研究材料无法支持的事实、场景、对话、数字或因果
- 不把“缺乏具体”误修成“伪造具体”
- 不为了结构整齐把所有段落修成相同长度和相同句式
- 不用密集金句、口头禅或粗口制造活人感
- 不抢跑 `style-refine` 的风格深化，但也不能磨掉初稿已有的作者声音
- 实用文必须保住动作路径、适用条件和可见结果

## 修改顺序

1. 标出初稿中最该保护的段落：具体材料、知识来路、独特判断、自然停顿
2. 把用户反馈逐项定位到具体段落，区分必须修改、需要判断和仅供参考
3. 对照研究材料做事实、来源、引语、数字、因果和研究署名检查
4. 先修材料和逻辑，再修段落顺序和解释链
5. 为每段标出新增事实、动作、例子、区别、后果或不确定性，合并只换说法的段落
6. 清理伪具体、素材点名式开头、模糊研究背书、表演性中文、抽象顺滑词和已知模型惯用表达
7. 检查人文连接是否真的改变理解，情绪是否由材料支付
8. 检查 `style-profile.md` 的共同风格内核和当前生效的正文规则

## 执行方式

本节点由当前编排 Agent 根据初稿、用户反馈和研究材料直接完成，不调用外部写作引擎，也不先生成独立模拟审稿文件。

修改时应用 `human-writing-standard.md` 的改稿顺序。不要只做逐条替换，要检查一处修改是否影响前后推进和事实归属。

如果检查发现核心材料不足，先停在当前节点报告缺口。补充研究后再继续生成 `03_修改稿`，不要静默编造或跳过问题。

## 验证

保存前检查：

- 用户明确反馈是否逐项解决
- 事实、来源、研究署名、引语、数字和因果是否与研究材料一致
- 核心判断是否有研究材料托住
- 作者说话位置是否比初稿更清楚
- 每个段落是否真的带来新东西
- 已经成立的具体材料和独特判断是否被过度润色磨掉
- 深度文是否仍有现实摩擦和判断空间
- 实用文是否仍能让读者立即尝试
- 素材点名式开头、模糊研究背书和已知模型惯用表达是否已经处理
- 共同风格内核和当前生效的正文规则是否满足

## 输出

- 保存为当前文章目录下的 `03_修改稿.md`
- 提供标题、开头样段、结尾样段和结构或风格自检
- 停在 `Review Gate`
- 用户确认后必须进入 `style-refine`，不得跳过风格深化
